# 3D Tetris — クレーンゲーム型

クレーンゲームの筐体の中で遊ぶ3Dテトリス。上から吊られて降りてくる立体ブロックを、クレーンの移動・回転で狙いを定めて落とし、水平な一段を埋めて消す。

2Dテトリスを3Dにすると奥行きの把握が追いつかず、自動落下のままでは操作が破綻する。そこで落下の主導権をプレイヤーに渡し、「狙いを定める時間」と「落とす瞬間」を分離した。クレーンゲームという題材は、この構造をそのまま持っている。

ブロックは角丸で柔らかい質感。着地するとむにゅっと潰れ、吊られている間はぷるんと揺れる。目指す絵は「クレーンゲームの中のぬいぐるみ」。

## 画面の流れ

**スタート画面 → ゲーム画面 → リザルト画面** の1サイクル。リザルトから `R` でもう一度、`Esc` でタイトルに戻る。

リザルトに至る道は2つある。**1000点に到達すればクリア、デッドラインまで積み上げてしまえば失敗。** どちらもプレイ時間とスコアを表示する。

シーンは1つだけで、画面の切り替えはUIのオン・オフで行う。ロードを挟まないのでリトライが即座に始まり、リザルトの背後に最終盤面が残る。

## ゲームルール

| 項目 | 内容 |
|---|---|
| 盤面 | 底面4 × 4、プレイ領域は高さ8段 |
| ピース | 4セルのテトラキューブ8種（平面5種 + 立体3種） |
| 落下 | 自動落下なし。任意のタイミングでドロップ |
| 制限時間 | **なし。** 納得するまで考えてよい |
| 回転 | ワールド3軸それぞれ90度単位。全24姿勢 |
| 消去 | 水平レイヤー1層（16マス）が全埋めで消去。上の層が1段落ちる |
| スコア | 同時消去レイヤー数のみで決定（1/2/3/4層 = 100/300/700/1500） |
| 終了条件 | **クリア**: 1000点到達 ／ **失敗**: デッドラインまで積み上げ |
| 記録 | プレイ時間を計測し、リザルトで表示する |
| 難易度変化 | なし |

## 操作

右ドラッグで自由に視点を回せる（正面から左右90度まで）。ただし**操作の向きは筐体の正面に固定**されていて、視点を回しても変わらない。実物のクレーンゲームの操作レバーと同じで、覗き込む角度が操作の意味を変えたりはしない。

| 入力 | 動作 |
|---|---|
| `↑` `↓` `←` `→` | ピースを移動（奥 / 手前 / 左 / 右）。押している間だけ動く |
| `Z` / `Shift+Z` | X軸回転（奥・手前に転がす） |
| `X` / `Shift+X` | Y軸回転（水平にひねる） |
| `C` / `Shift+C` | Z軸回転（左右に転がす） |
| `Space` | ドロップ |
| **右ドラッグ** | 視点を回す |
| `Esc` | ポーズ |

タイトル画面では `Space` / `Enter` で開始、リザルト画面では `R` でもう一度、`Esc` でタイトルへ。

着地位置は**影だけ**で示す。ピースの真上から光を当て、真下の面にシルエットを落とす。ゴーストは置かない。3Dでは操作中のピースが常に視界にあるため、ゴーストは注意の代替にならず、山の中に同じ形が二重に存在するだけになるため。

## 技術構成

- Unity 6 / URP / Input System / UniTask
- プラットフォーム: PC（キーボード＋マウス）

### アセンブリ構成

```
Assets/_Project/
  Core/           ゲームロジック。MonoBehaviour も Transform も Time も使わない純粋C#
  Presentation/   描画・演出
  Input/          入力の受け取りと論理コマンドへの変換
  App/            組み立てと進行管理
  Tests/EditMode/ Core のみを対象としたテスト
```

依存の向きは一方向で、`Core` は他のどのアセンブリも参照しない。asmdefで強制している。

**設計の要は `Core` をUnityから切り離している点。** 24姿勢の回転・着地計算・レイヤー消去は目視での検証が難しく、ここを自動テストで固められるかがプロジェクトの成否を分ける。演出を全て0秒にしてもゲームは同じ結果で最後まで進行する。

座標はセル座標（`Vector3Int`、ロジック用）とワールド座標（`Vector3`、描画用）を分離し、変換はセル → ワールドの一方向のみ。
